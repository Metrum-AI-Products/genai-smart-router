# 16 — x402 Per-Request Overage Payment and Settlement (#506)

Plan version: **v1.0.0**  
Issue: [#506](https://github.com/sysadmin-metrum-ai/genai-smart-router/issues/506)  
Classification: **launch blocking**

## Role

The primary overage mechanism in the hosted product. When a request exceeds the plan's included allowance (#522), the router issues a standards-compliant HTTP 402 challenge. The client pays, retries, and the router verifies + settles exactly once before upstream work.

## Admission integration (#522)

Router admission order:

1. Validate subscription entitlement is active.
2. Check included-allowance remaining. If sufficient → reserve and admit (no x402).
3. If insufficient → compute x402 quote for the deficit. Issue challenge.
4. On valid proof: verify, settle, proceed upstream.
5. Emit settlement events to #523 ledger.

## Required

- Current x402 spec headers/body/version rules behind a protocol adapter.
- Configurable facilitator with TLS, exact host allowlists, timeouts, credential references.
- At least one official-compatible test scheme/network before production.
- Durable idempotency preventing double settlement or double upstream delivery.
- Never prompts, tool payloads, images, keys, or private wallet material in DB/logs/metrics.

## D12

Live production x402 facilitator enablement requires treasury/compliance approval. Staging must prove the full path with a test scheme.
