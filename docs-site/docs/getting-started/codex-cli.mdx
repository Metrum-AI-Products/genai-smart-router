# Codex CLI

Codex CLI can call GenAI Smart Router through the OpenAI Responses-compatible API. Use a router-issued caller token in an environment variable.

<DeploymentSpecificNote />

<div class="contactBanner">
  <p>For Codex CLI deployment access, contact <a href="mailto:contact@metrum.ai">contact@metrum.ai</a>.</p>
</div>

## One-Shot Check

Use one of the model group IDs returned by `/v1/models` for `model`. See [Available Models And Access](./available-models) if you need to check which groups your token can request.

Record the Codex CLI version used for deployment validation with `codex --version`; CLI flags can change over time.

<RouterCodeBlock>
{`
export METRUM_ROUTER_KEY="rtr_metrum_<user>_<project>_<env>_<key>_<secret>"

codex exec --ignore-user-config --ephemeral \
  --ignore-rules \
  --skip-git-repo-check \
  -c 'model="<allowed-model-group>"' \
  -c 'model_provider="metrum-router"' \
  -c 'model_providers.metrum-router.name="Metrum Router"' \
  -c 'model_providers.metrum-router.base_url="{{apiBase}}"' \
  -c 'model_providers.metrum-router.env_key="METRUM_ROUTER_KEY"' \
  -c 'model_providers.metrum-router.wire_api="responses"' \
  "Reply with exactly: router codex ok" </dev/null
`}
</RouterCodeBlock>

`exec` is required for these non-interactive flags. The top-level interactive `codex` command does not accept every `codex exec` flag.

## Tool Smoke

Agentic tool calls should be tested with real file and shell activity in a disposable directory. Tool-bearing requests bypass response caching because the filesystem and shell state are part of the result.

<RouterCodeBlock>
{`
codex exec --ignore-user-config --ephemeral \
  --ignore-rules \
  --skip-git-repo-check \
  --dangerously-bypass-approvals-and-sandbox \
  -c 'model="<allowed-model-group>"' \
  -c 'model_provider="metrum-router"' \
  -c 'model_providers.metrum-router.name="Metrum Router"' \
  -c 'model_providers.metrum-router.base_url="{{apiBase}}"' \
  -c 'model_providers.metrum-router.env_key="METRUM_ROUTER_KEY"' \
  -c 'model_providers.metrum-router.wire_api="responses"' \
  "Create codex_tool_smoke.txt containing exactly codex-tool-ok, run cat codex_tool_smoke.txt, then finish with codex-tool-ok." </dev/null
`}
</RouterCodeBlock>

## Image Smoke

Codex CLI supports image attachments with `--image`. Use the same deployment-defined coding model group for mixed code and image tasks. Some hosted examples use `big-coder` as a coding-oriented group name; your deployment may use a different group name. The router receives image attachments as OpenAI Responses image inputs and filters that request to multimodal tool-capable upstream targets inside the group.

<RouterCodeBlock>
{`
mkdir -p tmp/router-vision-smoke
curl -fsSL "https://cdn.learnopencv.com/wp-content/uploads/2018/06/04100007/receipt.png" \
  -o tmp/router-vision-smoke/receipt.png

codex exec --ignore-user-config --ephemeral \
  --ignore-rules \
  --skip-git-repo-check \
  --image tmp/router-vision-smoke/receipt.png \
  -c 'model="<allowed-model-group>"' \
  -c 'model_provider="metrum-router"' \
  -c 'model_providers.metrum-router.name="Metrum Router"' \
  -c 'model_providers.metrum-router.base_url="{{apiBase}}"' \
  -c 'model_providers.metrum-router.env_key="METRUM_ROUTER_KEY"' \
  -c 'model_providers.metrum-router.wire_api="responses"' \
  "Read the attached receipt image. Reply with only the merchant name." </dev/null
`}
</RouterCodeBlock>

Image-bearing Codex requests bypass router response caching. Usage records include `input_has_image`, image count, and VLM cost fields when the upstream returns enough usage detail.

For the full VLM routing configuration and equivalent API examples, see [Image Analysis And VLM Routing](../configuration/image-analysis-vlm).
