# Hosted Quickstart

Use the router endpoint for your deployment with a router-issued caller token. The token authenticates the caller to Metrum Smart LLM Router; provider keys stay server-side. The product can run on prem, in an enterprise cloud account, or as a Metrum-managed instance.

<DeploymentSpecificNote />

<div class="contactBanner">
  <p>Need an on-prem deployment, enterprise cloud deployment, or Metrum-managed instance? Email <a href="mailto:contact@metrum.ai">contact@metrum.ai</a>.</p>
</div>

## Environment

<RouterCodeBlock>
{`
export ROUTER_BASE_URL="{{origin}}"
export ROUTER_TOKEN="rtr_metrum_<user>_<project>_<env>_<key>_<secret>"
export ROUTER_MODEL="<allowed-model-group>"
`}
</RouterCodeBlock>

Model group names are deployment-defined. If this hosted deployment exposes example names such as `default`, `fast`, `small`, `medium`, `high`, `big-coder`, or `vision`, treat them as deployment policy names, not product-required names.

## OpenAI-Compatible Chat

<RouterCodeBlock>
{`
curl "$ROUTER_BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer $ROUTER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "'"$ROUTER_MODEL"'",
    "messages": [
      {"role": "user", "content": "Reply with exactly: router ok"}
    ]
  }'
`}
</RouterCodeBlock>

## OpenAI Responses

Use `/v1/responses` for Responses-compatible clients and agent frameworks.

<RouterCodeBlock>
{`
curl "$ROUTER_BASE_URL/v1/responses" \
  -H "Authorization: Bearer $ROUTER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "'"$ROUTER_MODEL"'",
    "input": "Reply with exactly: router ok",
    "max_output_tokens": 32
  }'
`}
</RouterCodeBlock>

## Image Input

Image requests use the same deployment-defined router model-group names. The router filters image-bearing requests to targets that have passed vision validation and advertise `image` in `input_modalities`.

OpenAI-compatible chat:

<RouterCodeBlock>
{`
curl "$ROUTER_BASE_URL/v1/chat/completions" \
  -H "Authorization: Bearer $ROUTER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "'"$ROUTER_MODEL"'",
    "messages": [{
      "role": "user",
      "content": [
        {"type": "text", "text": "Read the receipt. Reply with only the merchant name."},
        {"type": "image_url", "image_url": {"url": "https://cdn.learnopencv.com/wp-content/uploads/2018/06/04100007/receipt.png"}}
      ]
    }],
    "max_tokens": 64,
    "stream": false
  }'
`}
</RouterCodeBlock>

OpenAI Responses:

<RouterCodeBlock>
{`
curl "$ROUTER_BASE_URL/v1/responses" \
  -H "Authorization: Bearer $ROUTER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "'"$ROUTER_MODEL"'",
    "input": [{
      "role": "user",
      "content": [
        {"type": "input_text", "text": "Read the receipt. Reply with only the merchant name."},
        {"type": "input_image", "image_url": "https://cdn.learnopencv.com/wp-content/uploads/2018/06/04100007/receipt.png"}
      ]
    }],
    "max_output_tokens": 64,
    "stream": false
  }'
`}
</RouterCodeBlock>

Anthropic-compatible Messages:

<RouterCodeBlock>
{`
curl "$ROUTER_BASE_URL/v1/messages" \
  -H "Authorization: Bearer $ROUTER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "'"$ROUTER_MODEL"'",
    "max_tokens": 64,
    "messages": [{
      "role": "user",
      "content": [
        {"type": "text", "text": "Read the receipt. Reply with only the merchant name."},
        {"type": "image", "source": {"type": "url", "url": "https://cdn.learnopencv.com/wp-content/uploads/2018/06/04100007/receipt.png"}}
      ]
    }]
  }'
`}
</RouterCodeBlock>

Image-bearing requests bypass response caching. Usage logs include image count, image-token counts when the upstream reports them, calculated VLM cost, and upstream-reported billed cost when available.

For dedicated vision route configuration, pricing metadata, and CLI image smokes, see [Image Analysis And VLM Routing](../configuration/image-analysis-vlm).

## Model Discovery

`/v1/models` is filtered by the caller token allow list.

<RouterCodeBlock>
{`
curl "$ROUTER_BASE_URL/v1/models" \
  -H "Authorization: Bearer $ROUTER_TOKEN"
`}
</RouterCodeBlock>

If a caller token is limited to a smaller set of deployment-defined groups, other groups will not be listed and cannot be requested.

## Python Client

The router accepts OpenAI-compatible SDK traffic. This example creates an isolated `uv` project and calls the hosted router through `/v1/chat/completions`.

<RouterCodeBlock>
{`
mkdir smart-router-python-example
cd smart-router-python-example
uv init --bare
uv add openai

cat > smoke.py <<'PY'
import os
from openai import OpenAI

router_base_url = os.environ["ROUTER_BASE_URL"].rstrip("/")
router_token = os.environ["ROUTER_TOKEN"]
router_model = os.environ["ROUTER_MODEL"]

client = OpenAI(
    base_url=f"{router_base_url}/v1",
    api_key=router_token,
)

response = client.chat.completions.create(
    model=router_model,
    messages=[
        {"role": "user", "content": "Reply with exactly: router ok"},
    ],
    max_tokens=32,
)

print(response.choices[0].message.content)
PY

export ROUTER_BASE_URL="{{origin}}"
export ROUTER_TOKEN="rtr_metrum_<user>_<project>_<env>_<key>_<secret>"
export ROUTER_MODEL="<allowed-model-group>"
uv run python smoke.py
`}
</RouterCodeBlock>

The same token and model-group rules apply to SDK calls: `/v1/models` shows only the groups that the token is allowed to use, and provider credentials remain server-side.
